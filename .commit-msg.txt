feat(chat): show the session's total tokens in the context readout

The context readout answers "how full is the window right now". It does not
answer "how much has this session spent", which is the question when a session
has been running a while and the percentage barely moves.

The number needed for that already exists and costs nothing to read:
`Session.tokens` is a server-maintained aggregate, sitting on the session record
next to `cost`, and OpenCode pushes it live through `session.usage.updated`.
Reading it needs no message history at all - which is the point, since a long
session holds far more history than the UI has paged in. Summing the loaded
messages would silently under-report, and loading the rest to be exact is the
cost this avoids.

So this adds the line, not the plumbing: an optional `sessionTokens` on
ContextUsageDisplay, fed from `useSession` in the three surfaces that render
it (header, VS Code, mini chat). One tooltip row, no new panel and no new
request.

`sessionTotalTokens` sums the reported fields rather than preferring `total`.
That is deliberate and the opposite of `contextTokensFromBreakdown`: `total` is
the last round-trip's window size, so preferring it here would report a large
context window as the session's spend. A test pins the difference.

A session that has spent nothing hides the line rather than showing 0, matching
how the cost row already behaves.
